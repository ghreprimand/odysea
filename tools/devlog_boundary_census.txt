# Published devlog entries that carry no conforming boundary above them, in
# reading order: the live record first, then each archive most recent first,
# each file top to bottom.
#
# The boundary convention was written down long after the record started, and
# the record was inconsistent before that. This file records exactly which
# published boundaries do not meet it, so that the rule can be enforced on new
# entries without demanding that published text be rewritten.
#
# It is a census, not an exemption list. The gate compares the record against
# it in both directions: a boundary missing here that does not conform is a new
# violation, and a boundary listed here that has acquired a separator is a
# published entry that was silently repaired. Both are refused. An exemption
# would permit the second, and the second is the outcome this file exists to
# prevent - published text is not corrected in place, by hand or by a merge
# resolution that normalises whitespace.
#
# Entries are keyed by heading alone, because a heading is fixed for the life
# of the record while the file holding it changes every time the record is
# split. A listed entry that becomes the first entry of an archive part has no
# entry boundary above it any more; it keeps its line here, and the opening of
# the file it now heads is checked by the file-opening rule instead.
#
# Lines that do not begin with a heading marker are ignored. Nothing may be
# removed from this list: it is the record of what was published, and the
# gate holds it to a count floor for that reason.
